1. Is everything really processed locally?

Yes. Every document operation — merging, splitting, compression, image conversion, OCR, signing, batch jobs, in-place text edits, annotations, page management, watermarks, export, forms/redaction/bookmarks and text-to-PDF — runs on your own machine through bundled local engines (PDFium, qpdf, Tesseract and Rust libraries). There is no upload endpoint and no server that receives your documents; no cloud AI or server-side conversion path exists.

The app can make three enumerable network requests, none carrying file content: one-time activation, an optional update check, and an optional OCR language-pack download you trigger yourself (a public dictionary, URL contains only a language code). We do not claim "zero network requests" — we claim file contents and file names are never uploaded. See question 15 and the privacy notes.

You do not have to take our word for it: the verify page shows how to check with a packet capture on Windows and macOS.

2. Can I use it fully offline, with no network at all?

Yes, after a single first-time activation. That activation needs an internet connection to validate the licence key; the result is cached as a signed local token. After that, every document-processing feature works fully offline. There are two other possible requests, both optional: an update check (switch it off in settings) and the download of an OCR language pack (only happens if you click "Install language pack").

We do not claim "zero network requests" — we claim file contents and file names are never uploaded and that all three request types are enumerable and verifiable. See the privacy notes for exactly what each contains and the verification guide for the packet-capture steps.

3. How accurate is OCR, and what are its limits?

Our acceptance targets are at least 95% for English and at least 90% for Simplified Chinese on clean, standard test scans (PRD §7 / §14). These are measured targets, not a guarantee for every document.

Local OCR works well on clear scans and simple layouts. Accuracy can drop on complex tables, handwriting, low-resolution or skewed scans, stamps over text, and mixed or unusual fonts. For those cases we would rather say the result may be imperfect than overpromise. You can select a page range and export either a searchable PDF (text layer) or plain TXT. We do not offer cloud OCR as a fallback.

English and Simplified Chinese are bundled. 42 languages are supported in total; the other 40 can be installed on demand from the "Print & extras" panel. That install is the app's only runtime network request you trigger — it downloads a public dictionary file whose URL contains just a language code. Recognition itself always stays on your machine; the bundled languages work with no connection at all.

4. Does compression keep the text layer and bookmarks?

Yes. Compression re-encodes and downsamples the images inside the PDF; it does not rasterise the page or remove existing text. The text layer stays selectable and bookmarks are preserved. The acceptance criterion is the target size within ±10% with text still selectable.

Trade-off: stronger compression means lower image quality at some point. We show a quality tier and an estimated/actual size so you can judge the result instead of guessing.

5. What about encrypted or password-protected PDFs?

We support files whose password you already know: enter it to open the file, and we can remove that known password from the output. If the password is wrong you get error E1003; if a password is required you get E1002.

We do not crack passwords, bypass DRM, or recover forgotten passwords. Encryption cracking is an explicit non-goal (PRD §19).

6. How do signatures and form flattening work?

You place a handwritten or image signature by dragging it onto a page and resizing it. Form fields can be filled in. “Flatten” bakes the field values and signature into the page content so they can no longer be edited, which is what most recipients expect.

The acceptance criterion is that the signed file opens correctly in Adobe Reader and that flattened fields are no longer editable. A signature here is a visual mark, not a cryptographic digital certificate / eIDAS-style signature.

7. How do the trial and activation work?

The 7-day trial is full-feature and needs no email or account. To keep using export after the trial, you buy a PAYONCE-XXXX-XXXX-XXXX key. The first activation does one online licence check, then a signed token is cached locally (Ed25519) so the app works offline afterwards.

Activation sends only the key and an irreversible machine-fingerprint hash — never file contents, file names, or document metadata. Details: privacy.

8. Does it work when the network is disconnected?

Yes. Once activated, all fifteen tools work with Wi-Fi and Ethernet turned off — merge, split, compress, image conversion, OCR, sign, batch, edit text, annotate, page management, watermark, export, forms/redaction/bookmarks, text-to-PDF, and printing/mail. The only actions that need a connection are the first activation, an optional update check, and installing an extra OCR language pack (an optional download you trigger yourself; English and Simplified Chinese are bundled). Block the app in your firewall and everything else still works — see the offline test.

9. What happens when the trial ends?

Only export is limited; the app returns error E2005. Your original files and previously exported files are never deleted, moved or modified, and the app does not reach into your folders. Activating a key restores export immediately. This behaviour is a hard rule (CONTRACT §1): trial expiry must never delete or rewrite user files.

10. Can I turn off automatic update checks?

Yes. Update checking is optional and can be disabled in settings. Updates are signature-verified (Tauri Updater with a minisign public key); a failed update can be rolled back. With update checks off and no language pack installed, the only remaining network request is the single first activation — and the app continues to work offline either way. Installing an optional OCR language pack is a separate, user-triggered download of a public dictionary; its URL contains only a language code.

11. Why does macOS block the app, and is it notarized?

Current status, stated plainly: the macOS build has not been produced, signed or notarized yet. The Windows installer exists for internal testing but is not Authenticode-signed; neither build is ready for public distribution. The CI workflow includes the intended path — build both architectures, combine them into a universal binary, sign with an Apple Developer ID, notarize with notarytool and staple — but it has not been run on Apple hardware. Distribution will be direct, not through the Mac App Store, because App Store sandboxing would restrict the bundled sidecars and arbitrary file access.

Once a notarized build is actually released, Gatekeeper should open it without warnings. If you see a “cannot be opened” warning on an official build, contact us rather than bypassing Gatekeeper.

12. Can you edit text in a PDF? What about Word / Excel conversion?

Yes for in-place text replacement. If you spot a typo while reading, use Edit text to find and replace it directly in the original PDF — no Word round-trip, no Acrobat subscription. It works on selectable text (scans need OCR first), supports Chinese, and does not reflow the page. If the embedded font lacks a glyph for your new text, PayOnce PDF returns a clear error instead of writing garbage or question marks. Longer replacements may visually overlap the text to the right, so please eyeball the result.

Not yet for a Word-like visual editor (cursor editing, paragraph reflow, dragging images or shapes), and not for high-fidelity conversion. We do export the text layer to TXT, HTML, DOCX and XLSX on your machine, but tables, images and layout are not restored. Commercial SDK-based conversion like some free editors offer is a known gap: achieving it would require a licensed SDK or bundling a ~200 MB office suite, which conflicts with our installer size and one-time price. We would rather state the limit than pretend a mangled table is a conversion.

The reverse direction is also covered, with the same honesty: the Text to PDF tool turns TXT / CSV / HTML into A4 pages (with an embedded system CJK font for Chinese). It is plain-text layout, not an Office converter — HTML tags are stripped, scripts are not executed, CSS is not rendered, and no tables, images or styling are restored.

This is a scoped decision, not an oversight. See the not-supported list and the feature grid.

Windows 10 1809+ (x64) and macOS 11+ as a universal binary (Apple Silicon and Intel). PDF 1.4–2.0 and password-protected PDFs with a known password. There is no mobile app, no web version and no browser extension.

15. What exactly does the app send over the network?

Exactly three kinds, none containing file content or file names: (1) a one-time activation carrying the licence key and an irreversible machine-fingerprint hash; (2) an optional update check carrying only version/platform identifiers; (3) an optional, user-triggered download of a public OCR dictionary from raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/<lang>.traineddata, where the URL contains only a language code. There is no telemetry, no analytics, no crash upload, and no cloud document processing or AI endpoint. We therefore no longer say "zero network requests" — the precise, verifiable promise is file contents never leave your computer, and all three requests are enumerated here. See the privacy notes and the verification steps.

16. Free PDF editors exist. Why would I pay $39?

Fair question, and we would rather answer it than dodge it. Free desktop editors such as PDFgear are genuinely capable and free — PDFgear can even edit existing PDF text in place — and for most everyday jobs they are a perfectly good choice. We benchmark our feature list against them rather than pretending they do not exist.

Three things we can promise that a free tool cannot, based on its own published statements (verified 2026-11-16):

  • Your file contents never leave your computer. Some free editors send document content and chat text to a cloud LLM after an explicit consent prompt, and their own statement acknowledges server-side processing for advanced features. PayOnce PDF has no cloud document-processing path at all. We make three enumerable network requests (activation, optional update check, optional public OCR dictionary download), none of which carries any file, file name or user data; the third is a download you trigger, not an upload. You can verify all of this with a packet capture (how).
  • The price will not change under you. A free editor's own statement says it may add paid options for AI features, high-accuracy OCR and complex conversions in the future. Ours is $39 once, with a written 12-month 1.x update boundary. No trial-to-paid surprise, no credit card on file.
  • Batch jobs are auditable. Point at a folder, apply one of nine operations to every file, and get a report.csv with per-file error codes. A failed file is recorded and never silently dropped, and no input file is ever overwritten in place.

If none of those three matter to you, use the free tool — we mean that. We are not trying to win on feature count alone; a free product with a larger team will usually win that race. We are trying to be the one you can verify.

Where we are still behind: high-fidelity Word/Excel/PPT conversion (we export the text layer only), a Word-like visual editor, editing images/shapes/links, stamps and drawing, checkbox/radio/dropdown form fields, nested bookmarks, an in-app print preview, automatic mail attachments, mobile and web versions, and a signed macOS build. Form creation (text fields), true redaction, top-level bookmarks, printing, mail and 42 OCR languages are now included — see the feature grid. We do not hide the remaining gaps behind vague wording.

17. Can I create form fields, redact text and manage bookmarks?

Yes, in the Objects tool (three modes). Create form adds standard AcroForm text fields (single-line, multiline, required) as Widget annotations with /NeedAppearances true, so readers such as Adobe Reader and PDFgear generate the appearance and let you type into them. Existing form fields are preserved, not overwritten.

Redaction is real: we delete the underlying text object before drawing the black box, so copying from the resulting PDF cannot recover the original words — unlike a black rectangle drawn over still-selectable text. It works on selectable text only; scans need OCR first. Please open the output and double-check the sensitive content is gone.

Bookmarks can be listed, replaced as a set, added, renamed and deleted via a rebuilt /Outlines tree. Honest limits: top-level bookmarks only (no nesting), and bookmarks do not automatically follow page numbers after pages are inserted or deleted.

Form creation currently offers text fields only — no checkboxes, radio buttons, dropdowns, calculation scripts or signature fields.

18. Do watermarks and text-to-PDF support Chinese?

Watermark text: yes. When the watermark contains non-Latin characters, PayOnce PDF embeds a system CJK TrueType font and writes the text into a real text layer (horizontally centred, grey). Font size applies; rotation and independent opacity do not apply to Chinese watermarks. If no system CJK font is found, you get a clear error rather than boxes or mojibake. Headers and footers remain Latin-only (Helvetica/WinAnsi) and will error on Chinese input rather than writing garbage.

Text to PDF: yes. TXT, CSV and HTML sources become A4 pages at 11pt with automatic pagination, using an embedded system CJK font so Chinese renders correctly. This is plain-text layout, not an Office converter: HTML tags are stripped, scripts never run, CSS is not rendered, and no tables, images or formatting are restored. For a faithful result, export the PDF from the original application instead.

19. How do printing, mail and OCR language packs work — and does that need the internet?

Printing hands the file to your system's default PDF viewer (Windows Start-Process -Verb Print, macOS lp). The print dialog belongs to that viewer; there is no in-app print preview. Mail opens a mailto: draft with a pre-filled subject and body; because mailto cannot attach files reliably across platforms, you add the PDF in your mail client manually. Neither uploads anything.

Language packs are the one case that uses the network. In "Print & extras" you can install any of 42 whitelisted Tesseract languages (English + Simplified Chinese are bundled). Clicking install downloads a public .traineddata dictionary from raw.githubusercontent.com; the URL contains only the language code and the request carries no file, file name, path, machine fingerprint or user data. The download is written to a temp file and swapped in only after validation (undersized responses are discarded, existing packs are untouched). OCR itself still runs entirely on your machine.

So the precise promise is: file contents never leave your computer, and there are exactly three enumerable request types (activation, optional update check, optional language-pack download). We do not say "no network requests at all". If you never install a language pack and switch off update checks, the first activation is the only request the app ever makes. See privacy and the verification guide.

20. What is PayOnce PDF's main use case, then?

In-place revision of a PDF you are reading, on a desktop, offline, for a one-time price. You spot a wrong date, a name that should be hidden, or a page that needs a note — you fix it in the original file instead of converting to Word and back. We are deliberately not an all-in-one suite.

We split the product into four layers: reading and annotating is the workspace (free readers do it too, so we do not charge for it); in-place revision is the only paid job (edit existing text, annotate, true redaction, watermark / page numbers, page management); conversion and OCR are included helpers but never the headline — we export the text layer and do not promise pixel-faithful Word/Excel output; layout-faithful conversion, a Word-like visual editor, cloud AI, mobile apps and sync are explicitly out of scope.

Why this one? In our 300-sample study, 40% of 81 valid pain points were about pricing and subscriptions and 11% about editing and forms — the complaint was the billing, not a missing feature. So we picked the one job where “no subscription, no upload, one price” is itself the reason to buy. See docs/primary-use-case-decision.md for the market and unit-economics reasoning.

21. Adobe Acrobat Reader is free — why would I pay to change a few words?

Because the free Reader cannot change existing PDF text. It views, prints, comments, highlights, fills and signs; editing existing words or images requires a paid Acrobat plan (checked against product documentation and independent comparisons, 2026-11-20). The usual workaround is converting the PDF to Word, editing there, then exporting back — exactly the round-trip we remove.

Our Edit text tool replaces text directly in the original PDF, locally, without reflow. It works on selectable text (scans need OCR first), supports Chinese, and returns a clear error when the embedded font lacks a glyph instead of writing garbage. Longer replacements can visually overlap neighbouring text, so please eyeball the result after saving.

On price: Acrobat Pro is roughly $239.88/year on an annual plan; PayOnce PDF is $39 / ¥199 once, with the licence itself never expiring and a written 12-month 1.x update window. We are not claiming feature parity with Acrobat — see question 16 for the gaps. We are claiming one narrow job, done offline, without a subscription.

22. Can I just select the words on the page and change them?

Yes, on the desktop app. Drag over words on the rendered page and PayOnce PDF highlights the characters it actually found. From there you can change this one spot directly: the selection rectangle (in PDF points) goes to the local engine, which rewrites only the text object under your cursor. Other identical words on the same page are left alone, and the result is saved next to the original as name_edited.pdf and shown in the preview.

The other route feeds the same selection into Edit text, Annotate or Redact, which still locate text by its string — so that path requires a unique match and blocks silently changing every occurrence.

What we deliberately do not claim: this is not a Word-like click-and-type canvas, it does not reflow paragraphs, and direct editing is limited to one line of continuous text. Cross-line selections, rotated pages (/Rotate ≠ 0), scans without a text layer, pages above 60,000 characters, PDFs whose text layer order does not match the content stream, and browser preview mode are refused with a reason instead of guessed at. Nothing is uploaded and no temporary file is written for this step.

You do not have to re-import the file between edits. After the first change the preview switches to name_edited.pdf, and dragging over another spot keeps editing that file: every further change is folded into the same *_edited.pdf, the preview refreshes in place without jumping back to page 1, and your original stays byte-for-byte untouched. One caveat: there is no undo — each click overwrites the result file, so copy it aside if you need intermediate versions. Going back to the original and editing again starts a fresh result file rather than discarding the earlier one.

What you can type depends on the font already in the file, not on a character list we chose: English and ASCII, CJK when an embedded font contains those glyphs, and Latin-1 symbols such as ± ° µ × ÷ are all editable, even in standard non-embedded Helvetica. Math symbols like ≈ ≤ ≥ ∑ ∫ √ π Ω work when the PDF embeds a font that has them, and are refused with an explanation when it does not. Subscripts and superscripts are separate small-font text objects, so dragging across a whole H₂O is refused (edit the superscript on its own instead) — otherwise the small text would be flattened to body size. A fraction is a numerator, a drawn rule and a denominator, so it cannot be edited as one unit. If the font has no glyph for the character you typed, nothing is written at all: the output is discarded and your original file stays byte-for-byte untouched.
