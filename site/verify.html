Verifiable by design

Do not take our word for it. Check the traffic.

File contents never leave your computer. PayOnce PDF can make exactly three kinds of network requests, none containing file content or file names. Here is how to confirm that on your own machine.

Your files never leave this computer.

The claim, stated precisely

What you should expect to see.

We do not claim "zero network requests". We claim file contents and file names are never uploaded, and that every request the app can make is on this list. During any document operation (merge, split, compress, image conversion, OCR, sign, batch, edit text, annotate, watermark, export, forms, redaction, bookmarks, text-to-PDF) there should be no new outbound connection at all from the PayOnce PDF process. The one deliberate exception is a language-pack download that you trigger yourself.

#RequestWhen it happensPayloadContains file content?
1First-time activationOnce, when you enter a licence keySmall JSON: licence key + irreversible machine-fingerprint hashNo
2Optional update checkOn launch, only if enabledSmall GET: version, platform, architectureNo
3Optional OCR language pack (download, not upload)Only when you click "Install language pack"GET for raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/<lang>.traineddata; URL has only a language code, fixed User-Agent, no request bodyNo
Turn the update check off and never install a language pack, and the single activation is the only network request the app will ever make. After that first check, all fifteen tools work with the network fully disabled. Activation and update checks are tiny (a few KB); a real PDF upload would be orders of magnitude larger and appear as a POST/PUT with a multipart or binary body. Request 3 is inbound — an inbound dictionary of a few MB is normal, an outbound body of that size is not.
Endpoint hostnames are TODO(activation host) and TODO(update-check host) — placeholders until launch. The updater URL currently in the build config is a placeholder. We will publish the real hostnames here so you can match them against your capture. The language-pack host is not a placeholder: it is fixed as raw.githubusercontent.com, path /tesseract-ocr/tessdata_fast/main/<lang>.traineddata.

Before you start

Prepare a “canary” file.

A canary is a unique string placed inside a test document. After capturing, you search the capture for that string; if it never appears, no document bytes were transmitted. Use the same idea for the PDF header marker %PDF-.

  1. Pick a unique marker, for example PAYONCEPDF-CANARY-8F3A91, that does not appear anywhere else on your machine.
  2. Create a small test PDF containing that marker (for example a text note converted to PDF with any local tool, or a page you annotate). Keep it simple: 1–3 pages.
  3. Optionally make a second, larger file (a 20 MB scan) so any real upload would be obvious by size.
  4. Close unrelated network-heavy apps (browsers, cloud sync, mail) so the capture is easy to read.
  5. Note your machine's local IP address (ipconfig on Windows, ifconfig on macOS) so you can filter outbound traffic.
A note on honesty: activation, update checks and language-pack downloads use HTTPS, so Wireshark shows you the destination, size and timing but not the decrypted body. To read that body, use Fiddler's HTTPS decryption (below) — you should see only a short JSON with the key and hash for activation, and an empty request body for the language pack; never a PDF.

Windows · Wireshark

Capture and inspect the packets.

  1. Install Wireshark (the installer includes Npcap; accept the Npcap driver). Reboot if prompted.
  2. Launch Wireshark and select the interface actually carrying traffic (Wi-Fi or Ethernet). Double-click it to start a capture.
  3. If the app is not activated yet, activate it now and note the one request; otherwise skip this step.
  4. With the capture running, open PayOnce PDF and run a real operation on the canary file: merge it with another PDF, compress the 20 MB scan, and run OCR on a few pages. Do all three so you cover different code paths.
  5. Stop the capture (red square). Save it as a .pcapng file for your records.
  6. Apply a display filter for outbound traffic from your machine, e.g. ip.src == 192.168.1.50 && tcp (replace with your IP). Add dns || tls.handshake.type == 1 to list connection attempts.
  7. Use Edit → Find Packet (Ctrl+F), choose “String” and “Packet bytes”, and search for PAYONCEPDF-CANARY-8F3A91, then for %PDF-. Both must return zero matches.
  8. Check Statistics → Conversations (TCP tab): while you were processing documents there should be no new conversations opened by PayOnce PDF. The only conversations should be the activation host, (if enabled) the update host, and (only if you installed a language pack) raw.githubusercontent.com.
  9. Display-filter http.request.method == "POST" || http.request.method == "PUT". A document upload would show up here with a large body. Expect no such request tied to file processing.
  10. Compare sizes: activation/update requests are tiny (a few KB). A 20 MB scan leaving the machine would produce a sustained multi-megabyte transfer — its absence is itself evidence.

Windows · Fiddler

Decrypt HTTPS and read the activation body.

Fiddler Classic acts as a local proxy and can decrypt HTTPS, which lets you read all three request types in plaintext.

  1. Install Fiddler Classic and open Tools → Options → HTTPS; enable Decrypt HTTPS traffic and trust the Fiddler root certificate when prompted. Also enable Capture HTTPS CONNECTs.
  2. On the Connections tab confirm Fiddler is acting as the system proxy (port 8888). Fiddler sets this automatically for most Windows apps.
  3. Open the Filters tab and use Client Process → Show only traffic from to select payoncepdf.exe (or enable the Process column in the session list and sort by it).
  4. Launch PayOnce PDF and, if needed, activate once. Run the canary merge / compress / OCR operations.
  5. Inspect the session list. You should see at most three hosts: the activation endpoint, (if enabled) the update endpoint, and raw.githubusercontent.com only if you deliberately installed a language pack. All other entries belong to other processes and should be filtered out.
  6. Double-click the activation session and open the Inspectors → TextView / JSON tab. Confirm the request body contains only a licence key and a hash — no file name, no path, no %PDF- bytes, no canary string, no multipart form.
  7. Confirm the update-check session is a small GET with version/platform identifiers only, and that there is no request carrying the canary marker or a large body.
  8. If you installed a language pack, confirm that session is a GET with an empty body, the path ends in /<lang>.traineddata with no filenames or identifiers, and the response is a dictionary file. Search the capture again for the canary string and %PDF-: still zero matches.
Fiddler changes the traffic path by inserting its own proxy and certificate. Use it to read the decrypted bodies, then cross-check the raw picture with Wireshark. A VPN or corporate proxy can also add hosts that are not PayOnce PDF — filter by process and by the published endpoint hostnames.

macOS · Little Snitch

Watch connections per process.

Little Snitch shows, per process, every connection attempt with bytes sent and received — the clearest way to see that processing a document opens no connection.

  1. Install Little Snitch (a third-party tool you install yourself; it is not part of PayOnce PDF) and open Network Monitor.
  2. In the search/filter box type PayOnce PDF so only that process's connections are listed.
  3. Launch PayOnce PDF. If it is not activated, allow the single activation connection; otherwise proceed without any approval.
  4. Run the canary merge / compress / OCR / sign / batch operations. Watch Network Monitor in real time: no new connection should appear for PayOnce PDF during those operations.
  5. For a stronger check, create a temporary Little Snitch rule that denies all outgoing connections for PayOnce PDF, then repeat every operation. All fifteen tools (except installing a language pack) must still work and export files. That is the practical proof of “offline by default”.
  6. Review the connection list: at most the activation host, (if enabled) the update host, and (only if you installed a language pack) raw.githubusercontent.com. The first two transfer only a few KB; the third is an inbound dictionary. No sustained outbound upload in any case.

macOS · Wireshark

Raw packet capture on macOS.

  1. Install Wireshark. On first launch it may ask to install ChmodBPF so a non-root user can capture; approve it, then reopen Wireshark.
  2. Identify the active interface (en0 is usually Wi-Fi, en1 sometimes Ethernet; check with networksetup -listallhardwareports or ifconfig). Start a capture on it.
  3. Activate once if needed, then run the canary merge / compress / OCR operations with the capture running.
  4. Stop and save the capture. Filter outbound traffic with ip.src == <your-local-ip> && tcp.
  5. Use Edit → Find Packet → String → Packet bytes to search for PAYONCEPDF-CANARY-8F3A91 and %PDF-. Expect zero matches.
  6. Open Statistics → Conversations and confirm that no new conversations were opened by the app during document processing.
If you use both Little Snitch and Wireshark, Little Snitch gives you per-process attribution and Wireshark gives you the raw bytes. Together they cover both “which process” and “what left the machine”.

The strongest test

Run it with the network disconnected.

This test needs no special tools and is the most convincing one.

  1. Activate the app once while online (or stay in the 7-day trial, which needs no activation at all).
  2. Turn off Wi-Fi and unplug Ethernet — or, alternatively, create a firewall rule that blocks all outbound traffic for PayOnce PDF (Windows Defender Firewall outbound rule, or a Little Snitch deny-all rule on macOS).
  3. Launch PayOnce PDF and exercise all fifteen tools: merge, split, compress, PDF to images, images to PDF, OCR, sign, batch, edit text, annotate, page management, watermark, export, document objects (form / redaction / bookmarks), and text-to-PDF. Printing and mail call your system programs and need no network either.
  4. Confirm every operation finishes, export succeeds, and output files are written to the folder you chose.
  5. Confirm there is no “connect to the internet” prompt blocking a feature. With update checks enabled, the check simply skips when offline; it must not disable any tool.
  6. Optionally try "Install language pack" while offline: it should fail with a clear message and leave existing language packs untouched. It is the only action that needs a connection beyond activation.
  7. Reconnect the network. There should be no queued or delayed upload — nothing was queued in the first place.
Edge cases, stated honestly: if you have never activated, the very first activation requires one online check. Installing an optional OCR language pack also requires a connection, but only when you explicitly click it. With the update check disabled and no language pack installed, that single activation is the only request the app will ever make. After it, offline use of all fifteen tools is complete.

Build authenticity

Verify the update signature yourself.

Every installer ships with a .sig file, and the updater refuses a build whose signature does not match the public key embedded in tauri.conf.json. You need neither our private key nor our word to check it.

  • From the repository root: pip install cryptography, then python tests/verify-updater-signature.py.
  • It checks three things: the key id in the signature matches the bundled public key; the file signature is valid Ed25519 over BLAKE2b-512 of the installer; the global signature also covers the trusted comment (timestamp, file name, version) so it cannot be swapped.
  • It runs a negative self-test too — flipping one bit must fail. Exit code 0 = valid, 1 = invalid, 2 = missing or malformed input.
  • To check a different build: python tests/verify-updater-signature.py path/to/setup.exe, with the .sig file next to it.
This verifies update integrity, not code signing. The current Windows installer is an unsigned internal test build, and no macOS build has been produced, signed or notarized yet. See the FAQ release status.

If something looks wrong

How to report an anomaly.

If you observe document content leaving your machine, treat it as a serious bug and a breach of our promise. Please report it — do not just work around it.

  • Include: OS and version, PayOnce PDF version, exact date/time, the operation you ran, destination host/IP, protocol and port, and the byte size of the request.
  • Attach a redacted screenshot or a trimmed .pcapng containing only the relevant packets; remove anything sensitive first.
  • Describe the steps to reproduce, and whether the app was activated and whether update checks were on.
  • As an immediate mitigation, block all outbound traffic for PayOnce PDF with your firewall — the app is designed to keep working.
