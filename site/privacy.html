No data collected

We collect nothing. Your files stay on your machine.

No account, no upload of file contents or file names, no telemetry. This page lists every network request the app can make — all three of them — so you can check it yourself.

Your files never leave this computer.

What we do not have

The design principle is “default safe” (PRD §6). These are structural, not settings we might flip later.

  • No user accounts and no user database
  • No email collection, no sign-up, no mailing list inside the app
  • No telemetry, analytics, crash uploads or usage statistics
  • No file uploads and no upload endpoint in the app
  • No cloud storage, sync or server-side document processing
  • No advertising SDKs or third-party trackers
  • No cookies or scripts on this website (static HTML + one local stylesheet)
  • No document contents, names or metadata ever transmitted — not even in the optional language-pack download

Three request types, none carrying file content.

This is the complete list — we do not claim "zero network requests". We claim that file contents and file names are never uploaded, and that every request the app can make is listed here so you can verify it. If you observe anything else originating from PayOnce PDF, please report it.

Activation detail

The key and the irreversible fingerprint.

What is sent

The licence key and a one-way hash of a machine fingerprint (Ed25519-signed licence design, PRD §9.1). A hash cannot be reversed into the original hardware identifiers. There is no user identity attached to it.

Why a hash

The activation server needs to bind one key to one machine without learning who you are or what is on your disk. The result is cached as a signed local token, so no repeat calls are needed and offline use is the default.

You can confirm this yourself: capture the activation request and verify it contains only a small JSON body with the key and hash — no %PDF- bytes, no multipart upload, no document content. See the verification guide.

Local logs

Off by default, and deliberately minimal.

Local logging is disabled by default (PRD §6.3 / §10). If you turn it on to diagnose a problem:

  • It records only the operation type (for example merge or ocr) and the error code (for example E1002).
  • It does not record file names, paths, contents, sizes, or any document metadata.
  • The log file stays on your machine and is never transmitted; there is no remote logging endpoint.
  • You can turn it off again and delete the log at any time (see the user manual, “uninstall & log cleanup”).
