# PayOnce PDF ↔ UPDF 差距分析（2026-11-20）

> **2026-11-20 后续决策**：本文 §2/E 的价格与设备数结论基于改价前状态；现行价格 **$39 / ¥199**（早鸟 **$29 / ¥149**）与 3 台设备授权见 `docs/updf-parity-decision.md` §1 与 `config/product.json`。功能差距清单仍然有效。
> **F18 补记**：本文指出的「没有内置 PDF 阅读/预览视图」形态缺口已由 F17 + F18 补上（PRD §22.12、测试报告 §21）；但「按矩形精确只改框选那一处」仍未做，功能宽度与平台覆盖的差距不变，**真机未验**。

> 本文只做竞品差距盘点，**未改动任何代码、配置、价格或对外文案**。
> UPDF 侧资料检索于 2026-11-20，来源：UPDF 官网 / 官方版本日志 / PDF Association / Apple App Store / 第三方评测（G2、Capterra、PlugRoute、Office Software Marketplace）。
> PayOnce PDF 侧现状来自本仓库源码与 `docs/` 文档（PRD §19/§22.8、`docs/pdfgear-parity-matrix.md`、`docs/real-device-test-plan.md` §6、`docs/test-report.md` §16）。

## 0. 先纠正一个容易重犯的事实前提

**UPDF 的核心 PDF 工具链是本地离线的**。它的 OCR 是本地插件（Windows 约 1.68 GB、Mac 约 1.4 GB），编辑 / 转换 / 批注 / 表单 / 加密均在桌面端完成；**只有 UPDF AI、eSign 邀请签署、云同步需要联网并把文档送到服务端**（官方称 AI 运行在美国服务器，走 OpenAI 模型，声明不用于训练、不共享第三方，另有 ISO 27001 认证口径）。

因此：

- ❌ 不能说「UPDF 要上传文件，我们不用」——这在此前对标 PDFgear 时曾判断失误过一次，对用户指出的「它也是本地处理」做过更正，本轮不能重犯。
- ✅ 准确说法是：「**双方在核心 PDF 工具上都是本地处理**；差异只出现在 UPDF 的 AI / eSign / 云同步链路，以及我方把三类网络请求逐条公开、可抓包验证。」
- ⚠️ 官网中文首页现有一句「不必为了把文件留在自己电脑上而牺牲能力」，对 PDFgear 成立（AI 走云），**对 UPDF 核心工具不成立**——UPDF 同样「文件留本地且能力更强」。这句不宜作为对 UPDF 的攻击点。

另外，UPDF 的「4M+ 用户」「OCR 99.59%」「内存比 Acrobat 少 90%」「G2 Leader 2026」均为**厂商自述**，第三方未见独立复现；价格随大促浮动极大，本文数字均标注为观测时点，以结算页为准。

## 1. 一句话结论

**两者不是同一产品形态**：UPDF 3.0 是「打开一份文档 → 边读边编辑/批注/翻译 → 发起签署 → 跟踪状态」的**文档工作台**；PayOnce PDF 是「选文件 → 填参数 → 批量跑任务 → 输出文件」的**本地工具箱**。因此最致命的差距不是「少几个功能」，而是**我们根本没有文档视图**：用户看不到正在处理的那一页。

按对购买决策的杀伤力排序：**形态级 > 成熟度/可安装性 > 功能级 > 商业条款 > 平台生态**。

### F. 我方仍然守得住的（别把「不足」扩大化）

1. **无账号 / 无遥测 / 日志默认关闭**，三类请求逐条公开可抓包验证（相对 UPDF 的账号 + 云同步体系）。
2. **批处理 + 可审计失败台账**：`report.csv` 带 `error_code`、单文件失败不中断、不覆盖输入（第三方评测点名 UPDF 类产品的批量自动化仍有加强空间）。
3. **写后读回校验 / 不损坏原文件**：F10 改字结果必须能重新读回，否则删除输出并报错，是对低价编辑器「假成功」的硬防御。
4. **单档买断 + 无 AI 加购 + 无自动续费陷阱 + 更新边界写死**，收费确定性优于 UPDF 的「买断 + AI 年费 + 续订争议」。
5. **安装包 27 MiB**：相对 UPDF 177 MB + 1.4–1.68 GB OCR 插件，是真实且可量化的优势。
6. **授权本身不过期**（只是免费更新窗口 12 个月）。

## 3. UPDF 自身的短板（避免把竞品神化）

| 项 | 依据 |
|---|---|
| 免费版保存带水印，且有用户报告**原文件被水印污染且无法移除** | PlugRoute / r/pdf 用户反馈；建议只用副本试用 |
| OCR 在复杂版面、非标准字体、低质量扫描件、泰文/日文上易错；PDF→PPT 质量被诟病 | Capterra「OCR is a little weak」、G2 评价 |
| WYSIWYG 编辑不完美：一句话被切成多个文本框、格式不一致 | 第三方评测常见抱怨 |
| 大文件卡顿（与官方「2GB+ 流畅、内存少 90%」口径相反） | G2 / Trustpilot |
| AI 独立收费且不同页面标价不一致（$69 / $79.99；¥148 / ¥238），Pro 购买页默认勾选 7 天 AI 试用后自动转付费 | 第三方追踪 + Trustpilot 扣费投诉 |
| 退款政策严格、需提前 3 天取消订阅 | 官方退款条款 |
| Web 端只有 AI，不是完整编辑器；无 Google Drive / OneDrive 深度集成 | 官方功能说明 / 评测 |
| 「买断含终身大版本升级」与第三方评测口径冲突 | 官方 vs 评测 |

> 结论：UPDF 不是无懈可击，但它的短板集中在**免费版体验、OCR 精度、AI 收费与续订**；而我方的短板集中在**产品形态、功能宽度、可安装性与成熟度**。两者不在一个层面上，不能用「它有缺点」抵消「我们没做完」。

## 4. 建议：分三类处理

### P0 — 发布前必须补（不是功能差距，是「能不能卖」）

1. 修 `bundle.resources` 缺 `tessdata`，重建 NSIS 并重签名（BLOCK-02）。
2. 跑完真机 60 条用例 + Adobe Reader / Word / Excel 产物兼容性。
3. Windows Authenticode / EV 签名；macOS 实机构建 + Developer ID + notarize/staple。
4. 更新端点真实化、生产 minisign 密钥替换、升级链路实测。
5. 抓包验证三类请求，把「文件永不上传」从文档承诺变成可复现证据。

### P1 — 不补会直接影响转化（建议重新拍范围）

1. **内置 PDF 预览 / 阅读视图**：否则 A1/A3 使「就地改字」这个核心卖点在交互上不成立。
2. **授权设备口径**：明确是「一机一密钥」还是「一人最多 N 台」，并在定价页算清多设备成本；否则 E1 会成为评论区第一条质疑。
3. **获客漏斗**：是否提供不限时长的免费带水印版 / 只读版，或把 7 天试用延长。
4. **官网不支持清单**补齐与 UPDF 的对标项（WYSIWYG、14 种批注、eSign、云同步、移动端）。
5. **OCR 口径**：官网现在写「42 种语言」，但开箱只有 2 种、安装版还缺包；应先修好再宣传。

### P2 — 按你此前的指示暂缓，但要接受竞争后果

AI 问答、移动端、高保真 Word/Excel、eSign、云同步。这些是与 UPDF 同场竞争时的**结构性缺席**，定位上只能规避，不能硬碰。

### 定位建议

不要写「功能不弱于 UPDF」——在功能宽度上这是可被一秒证伪的。可防守的叙事是：
**「一次买断、无 AI 加购、无自动续费、无账号、文件不出门（除激活与语言包）、批量任务带可审计台账、27 MB 装完就能用」**。
这与 `docs/positioning-v2.md` 的「买断 = 不再被订阅 / 本地处理 = 信任卖点」一致，但要把「信任」从「对手会上传」改成「**我们把每一条网络请求都列出来，你可以抓包核对**」。

## 5. 需要你拍板的问题清单

1. 是否把「**内置 PDF 预览**」纳入范围？这是把 F10 从「能改」变成「好用」的最小闭环。
