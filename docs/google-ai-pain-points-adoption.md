# 借鉴 Google AI 痛点报告的改进清单（2026-11-22）

> 触发：用户提供 Google AI 研究报告《用户在使用 PDF 软件工具时感到最不爽的痛点》（附件，四类痛点：臃肿卡顿 / 付费陷阱 / 编辑转换灾难 / 碎片化与隐私焦虑）。
> 方法：逐条对照 `README.md` §1.1 的 16 工具清单与 `docs/requirements/PRD.md` §19 的范围决策，判定「已天然命中 / 可强化 / 需补强」，按**投入产出比**排序，不追功能宽度。
> 口径：与 `docs/defect-review-2026-11-21.md` 一致——**代码写完 ≠ 真机跑通 ≠ 商业可用**；本清单里的「收益」是产品层面的相对优势，不是已完成承诺。
> 边界：报告的痛点是行业普遍现象，其中「移动端重排」「高保真转换」之所以普遍，正因为解决代价极高。本清单**明确不把暂缓项翻案**。

---

## 0. 总览：这份报告对 PayOncePDF 意味着什么

四大痛点里三条（臃肿、付费陷阱、隐私焦虑）PayOncePDF 靠架构选型**已经天然解决**——问题不是「补功能」，而是**把已有优势变成用户看得见、可验证的东西**。唯一真正的产品短板是「编辑不重排」，它无法根治（PDF 底层是印刷品不是流式文档），但可以把**事后的免责声明前移成事前预警**（本轮已落地，见 §2 P0-1）。

| 痛点类别 | 判定 | 核心动作 |
|---|---|---|
| 1. 臃肿卡顿 / UI 改版反人类 | 已天然命中，**未量化** | 把「轻」做成可量化首屏指标；冻结工具入口布局纪律 |
| 2. 付费陷阱 | 已天然命中，**未前移到决策点** | 在导出那一刻亮出买断制；试用余量前置 |
| 3. 编辑转换灾难 | **部分命中，唯一真短板** | 改字宽度预警（已做）；导出预期提示；诚实边界不松口 |
| 4. 碎片化 + 隐私焦虑 | 已天然命中，**缺可验证感** | 断网可用标识 + 16 工具串成引导式工作流 |

## 1. 排序原则

投入产出比 = 用户可感知收益 ÷ 实现成本。优先级：

- **P0**：本轮已完成，或改动极小、直击痛点核心。
- **P1**：中等投入、收益明确，建议排入下个迭代。
- **P2**：需设计取舍或依赖外部条件，先记录不启动。
- **不做**：与已拍板范围冲突，或成本与「轻量买断」定位相悖。

## 2. 可执行清单

### P0 — 已落地 / 立即可做

#### P0-1. F19 改字宽度溢出预警 ✅ 本轮已实现

- **痛点对应**：报告 §3「文本修改极其痛苦——删几个字不会自动重排，导致局部留白或文字重叠」。
- **做什么**：提交前用原文字符框真实宽度估算新文字是否变长，变长就预警并要求确认，不再让用户改完才发现。
- **落点**：`src/lib/selection.ts`（`estimateRectEditWidth`）、`src/components/PdfPreview.tsx`（预警 UI + `overflowAck` 闸门）、`src/styles.css`（`.viewer-sel-overflow`）。
- **收益**：把 F19 最大的体验缺陷从「事后才知道」变成「事前可见」，且零引擎改动、零授权成本。
- **边界**：是估算不是精确测量，不改变不重排的根本限制，仍须目视核对。详见 PRD §22.24、测试报告 §35。
- **状态**：完成，40/0 单测 + typecheck + build 通过；真机未验。

#### P0-2. 把后端详细失败原因透传到状态栏 ✅ 本轮已实现

- **痛点对应**：报告 §3「微调极其费时费力」——用户最需要知道「为什么被拒绝」。
- **做什么**：`App.tsx` 的 `startJob` catch 原先用 `hintForCode(appErr.code)` 把后端详细 message 丢掉，F19 引擎写了极细的中文原因（「选区字号不一致」「文字层顺序与内容流不符」等），用户却只看到「操作失败，原文件未改动」。改为经 `describeErrorDetail(appErr)` 展示具体原因。
- **落点**：`src/lib/errors.ts`（新增 `describeErrorDetail`）、`src/App.tsx`（catch 分支）、`tests/error-detail.test.mjs`（7 条纯函数）。
- **收益**：极小改动，直接让所有「失败即拒绝」场景变得可诊断，减少用户反复试错。
- **边界**：中文业务原因完整展示（未自带安全语义时补「原文件未改动」）；多行堆栈 / Rust panic / JS 栈帧 / 超长 dump / 纯英文技术串（`IO error: ...`）一律甄别回退到稳定 code 文案，不泄漏内部实现。不影响 `describeError`（许可激活场景）既有行为。
- **状态**：完成，48/0 单测 + typecheck + build 通过；真机未验。

### P1 — 建议排入下个迭代

#### P1-1. 官网首屏量化「轻」

- **痛点对应**：报告 §1「启动与响应慢」「塞入云服务、AI 助手」。
- **做什么**：PayOncePDF 已是 Tauri 原生 + 无 AI + 无后台常驻，但官网首屏只有口号，没有数字。测出并亮出：冷启动时间、安装包体积、空闲内存占用、运行时网络请求仅三类（一次性激活 / 可选更新 / 用户主动装语言包）。
- **落点**：`site/index.html` 与 `site/index.zh.html` 首屏、`docs/real-device-test-plan.md`（补这三项测量用例）。
- **收益**：竞品的「重」是可感知的，我们的「轻」目前不可见；量化后是最低成本的差异化。
- **边界**：数字必须来自真机实测，不能编；这正是当前真机 0/78 未执行的部分，需先补测。与「不得宣称零网络请求」的既有口径一致。

#### P1-2. 导出那一刻亮出买断制 + 试用余量前置

- **痛点对应**：报告 §2「假免费真收费——完成编辑后点保存时突然弹充值」「订阅昂贵取消难」。
- **做什么**：把「一次买断 / 7 天试用 / 7 天退款 / 无自动续费」从定价页搬到**用户即将导出的决策点**；试用态在界面常显「还剩 N 天」，而不是等 E2005 弹出。
- **落点**：`src/App.tsx`（授权检查与 `startJob` 的试用分支）、`src/components/StatusBar` 相关、`site/pricing.html`。
- **收益**：竞品的软肋就在「最后一步」，我们把话术放在同一位置形成正面 contrast。
- **边界**：不得把试用限制包装成「惊喜」；余量必须真实、不误导。定价口径以 `config/product.json` 为准（$39/¥199）。

#### P1-3. 「断网可用」标识 + 把 16 工具串成引导式工作流

- **痛点对应**：报告 §4「工具割裂——为提取页面/水印/OCR/签章装多个软件」「涉密文件不敢用在线工具」。
- **做什么**：
  1. 在 UI 与官网加一个可验证的「本机处理 · 断网可用」标识（现有 `viewer-local` 只是画布角标，可提升为全局语义）。
  2. 把平铺的 16 个入口按**任务链**串起来，例如「扫描件改字」= OCR → 框选改字 → 导出；「合同修订」= 文档比对 → 改字 → 签名 → 加水印。给用户一条默认路径，而不是让他自己拼 16 个按钮。
- **落点**：`src/App.tsx`（侧栏分组 / 入口编排）、`src/components/Sidebar.tsx`、`site/index*.html`。
- **收益**：既强化隐私差异，又降低「工具箱不知道从哪下手」的门槛。
- **边界**：工作流是引导不是强制，任何工具仍可单独进入；不新增云端步骤。

#### P1-4. F14 导出前的版式预期提示

- **痛点对应**：报告 §3「PDF 转 Word/Excel 排版崩坏——字体丢失、表格错位、变成整张图片」。
- **做什么**：F14 只导文字层（不还原版式/表格/图片），这点已写在 UI/FAQ，但**点导出前**没有提示。在导出按钮旁或确认时明确「将保留文字，不还原版式与表格」。
- **落点**：`src/panels/`（F14 导出面板）、`src/App.tsx`（导出入口）。
- **收益**：与 P0-1 同一思路——把事后失望变事前预期，减少「下载完才发现是纯文本」的差评。
- **边界**：绝不暗示「支持高保真转换」；与 PRD §19 暂缓决策一致。

### 明确不做（与已拍板范围冲突）

| 项 | 报告对应痛点 | 不做的理由 |
|---|---|---|
| 移动端重排阅读 | §3「手机双栏/扫描版无法重排」 | PRD §19 明确暂缓；桌面双平台尚未签名公证，移动端更远。且该痛点之所以普遍，正因为重排引擎代价极高 |
| 高保真 Word/Excel 转换 | §3「转换排版崩坏」 | LibreOffice 为 MPL-2.0 且体积大（许可红线延后评估），与「轻量买断」相悖；继续用 F14 文字层导出 + 诚实边界 |
| 内置 AI 助手 / 云服务 / 协同 | §1「塞入花哨 AI 助手导致臃肿」 | 报告本身就批判这一点；PRD §19 L3 明确不做云端 AI 问答、账号、云同步。做它们等于把竞品的病复制过来 |
| 订阅制 / 免费增值 | §2「订阅昂贵取消难」 | 一次买断是本产品定位根基，改订阅等于自我否定 |

## 3. 一句话结论

报告的四类痛点里，我们**赢在架构臃肿、付费陷阱、隐私焦虑三条**，输在「编辑不重排」一条——而这一条是 PDF 格式的物理限制，无法根治，只能靠**把边界前移**（P0-1 已做）+ **把优势量化可见**（P1-1~3）来赢回体验。P0-1（宽度预警）与 P0-2（错误原因透传）均已落地；下一步最高性价比是 **P1-1（首屏量化）**，但需先补真机数据。
