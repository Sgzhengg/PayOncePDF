**结论**：本轮不追「功能宽度」，只修**竞品不会犯、而我们确实存在的缺陷**——静默数据损坏、假成功提示、状态串味、下载无校验。这些是质量底线，不是功能军备竞赛。

## 3. 本轮修复详情

### D1 链式状态串味

- **根因**：`chainableResultPath`（决定结果预览能否继续框选）和 `ownEditedRef`（决定能否原地覆盖 `*_edited`）在 `addItems` / `removeFile` / `moveFile` / `clearFiles` / `applySelection` / `onBackToInput` / 非链式 `startJob` 中均未清空。残留路径一旦与新结果路径重合，就会在非本会话产物上误开框选。
- **修法**：新增统一 `resetChainState()`，在上述所有入口调用；连续编辑路径 `opts.keepPreview === true` 明确**不清**（否则 F19 又退回「只能改一处」）。
- **验证**：`tests/defect-regression.test.mjs` 静态锁定 7 个入口 + 连续编辑白名单。

### D2 假成功提示

- **根因**：`onUsePage` 的 `setParams` 对无 `pages` 字段的工具是 no-op（`return prev`），但函数末尾**无条件** `setStatusText("已把第 N 页填入…")`。
- **修法**：先用当前 `params[activeTool]` 判断是否有 `pages` 字段；没有则提示「不使用页码，无需填写」并 return。
- **验证**：静态断言同时覆盖失败分支文案与正常分支成功文案。

### D3 表单扁平化中文静默损坏

- **根因**：`escape_pdf_string` 把一切非 ASCII 字符压成 `?`。标准 14 字体（Helvetica）不嵌字体，扁平化后中文永久损坏且无任何提示。
- **修法**：
  1. 新 `winansi_bytes()`：ASCII 与括号/反斜杠正确转义；**Latin-1（U+00A0–U+00FF）按单字节写出**（`± ° µ × ÷` 等此前也被误压成 `?`，一并修好）；非 WinAnsi 字符返回 `Err(char)`。
  2. `fill_and_flatten` 在**写入前**遍历所有字段值校验，含非 WinAnsi 字符直接返回 E1001，明确说明「已拒绝且不写出文件」，并给出替代方案（改用英文 / 关闭扁平化保留可编辑字段）。
  3. appearance 流改用字节拼接，避免 Latin-1 字节被 UTF-8 二次编码。
  4. 成功文案同步改准确。
- **验证**：4 条 Rust 单测（ASCII/Latin-1 转义、中文拒绝、`fill_and_flatten` 闸门、Latin-1 通过）。

### D4 OCR 下载无完整性校验

- **根因**：`install_language` 只检查 `bytes.len() >= 50_000`。CDN 404 页、网关占位页、截断下载都可能落盘，之后 OCR 静默失败且用户以为是语言包问题。
- **修法**：新增 `validate_traineddata()`：大小 50KB–32MB、protobuf 文件头 `0x18`、含 `0xFF` 二进制填充特征、非 HTML/JSON 文本开头。失败返回 `E1006`（OCR 专用错误码），不写临时文件。
- **验证**：2 条 Rust 单测——真实随包 `eng` / `chi_sim` 必须通过（防误杀），HTML / 错头 / 无填充 / 过小 / 过大五类伪造内容必须拒绝。
